# Ведомость комплекта документации

## на программное обеспечение лабораторной информационно-управляющей системы «Химические источники тока» (ЛИМС-ХИТ)

---

**Наименование изделия:** Программное обеспечение лабораторной информационно-управляющей системы «Химические источники тока».

**Краткое наименование:** **ЛИМС-ХИТ**.

**Техническое обозначение в исходном коде:** BADB (от англ. *Battery Assembly Database*, историческое обозначение, сохранено в коде и структуре базы данных для целостности кодовой базы).

**Обозначение документации:** BADB.00001-01 *(обозначение — @уточнить в системе обозначений ООО «РЭНЕРА»)*.

**Правообладатель:** ООО «РЭНЕРА» (ГК «Росатом»). Подразделение-разработчик — Центр химических источников тока.

**Область применения:** R&D химических источников тока (ХИТ) — электродные материалы, электролиты, сепараторы, ячейки и батарейные модули различных электрохимических систем.

**Версия ПО:** 1.0 (опытная эксплуатация).

**Дата формирования комплекта:** 22 апреля 2026 г.
**Дата последней актуализации:** 9 мая 2026 г.

# 2. Краткое описание содержания документов

## 2.1. Техническое задание (документ № 1)

Определяет требования к разработке программного обеспечения: назначение, область применения, функциональные, технические и специальные требования, в том числе требования к безопасности и надёжности. Используется как исходный документ для всех остальных документов комплекта и для приёмки.

## 2.2. Описание программы (документ № 2)

Описывает фактически реализованное программное обеспечение: его логическую структуру, используемые технические средства, порядок запуска, структуру входных и выходных данных.

## 2.3. Пояснительная записка (документ № 3)

Содержит обоснование проектных решений: выбор архитектуры, языков и технологий; логическую модель данных с ER-диаграммами по доменам; описание потоков данных; обоснование решений по безопасности.

## 2.4. Руководство оператора (документ № 4)

Описывает действия пользователя по работе с текущей vanilla v1 поверхности: вход, ведение справочников, page-local фильтры, record-open формы, пошаговое заполнение рабочих процессов, безопасные destructive-сценарии, работа с отчётами и экспортом.

## 2.5. Руководство системного программиста (документ № 5)

Содержит сведения для администратора: установка, настройка, ручные forward-only миграции, authoritative ledger `public.schema_migrations`, проверка `d032`/`schema_migrations` и `d031` на Windows/lab БД, резервное копирование, восстановление, обновление, обработка нештатных ситуаций.

## 2.6. Программа и методика испытаний (документ № 6)

Определяет порядок и методику проведения испытаний программы: перечень проверяемых функций, vanilla contract/smoke checks, миграционные проверки, ручные destructive-flow проверки, тест-кейсы с пошаговыми сценариями, критерии приёмки. Основа для «Акта по результатам опытной эксплуатации».

# 3. Порядок чтения документов

## 3.1. Для заказчика / приёмной комиссии

Рекомендуемый порядок:

1. Настоящая ведомость.
2. **ТЗ** (документ № 1) — что должно быть сделано.
3. **Руководство оператора** (документ № 4) — как этим пользоваться.
4. **Программа и методика испытаний** (документ № 6) — как это проверить.
5. Остальные документы — по необходимости.

## 3.2. Для системного администратора

1. Настоящая ведомость.
2. **Руководство системного программиста** (документ № 5) — установка, эксплуатация, бэкапы.
3. **Описание программы** (документ № 2), разделы 1–5 — технический контекст.

## 3.3. Для разработчика-сопровождающего

1. **Описание программы** (документ № 2) — структура кода.
2. **Пояснительная записка** (документ № 3) — почему это так устроено.
3. **ТЗ** (документ № 1) — требования, которые нельзя нарушать.

## 3.4. Для лабораторного оператора

Только документ № 4 — «Руководство оператора».
