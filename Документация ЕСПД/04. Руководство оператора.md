# Аннотация

Настоящий документ составлен в соответствии с ГОСТ 19.505-79 «ЕСПД. Руководство оператора».

Документ описывает действия оператора при работе с программным обеспечением **лабораторной информационно-управляющей системы «Химические источники тока»** (далее — **ЛИМС-ХИТ**; техническое обозначение в исходном коде — **BADB**). Документ предназначен для сотрудников Центра химических источников тока ООО «РЭНЕРА», выполняющих R&D-работы по разработке химических источников тока — электродных материалов, электролитов, сепараторов, ячеек и батарейных модулей.

Документ не требует от оператора специальных знаний в области информационных технологий. Предполагается базовое владение персональным компьютером и веб-браузером.

> **Примечание к черновику (версия 0.1):** в окончательной версии каждый раздел с интерфейсом будет дополнен скриншотами. В настоящей версии описание выполнено текстовым способом.

# 1. Назначение программы

Программное обеспечение **ЛИМС-ХИТ** — лабораторная информационно-управляющая система «Химические источники тока» (далее — программа, система; техническое обозначение в исходном коде — **BADB**) предназначено для:

- Ведения справочников материалов, поставщиков, рецептур, оборудования.
- Пошаговой регистрации процесса изготовления электродной ленты.
- Учёта партий нарезки электродов и индивидуальных электродов.
- Сборки и контроля качества батарей.
- Учёта электрохимических испытаний и циклирования.
- Автоматизированного расчёта научных показателей (ёмкость, N/P, энергетическая эффективность).
- Анализа и визуализации экспериментальных данных.
- Формирования печатных и электронных отчётов.

# 2. Условия выполнения программы

## 2.1. Требования к рабочему месту оператора

| Требование | Значение |
|---|---|
| Компьютер (ПК, ноутбук) | любой современный |
| Оперативная память | от 4 ГБ |
| Разрешение экрана | от 1366 × 768 (рекомендуется 1920 × 1080) |
| Браузер | Chrome 120+, Firefox 120+, Edge 120+, Safari 17+ |
| Сеть | доступ к корпоративной LAN ООО «РЭНЕРА» |

## 2.2. Требования к пользователю

- Умение работать с персональным компьютером, клавиатурой, мышью.
- Базовые навыки работы с веб-браузерами.
- Специальная подготовка в области информационных технологий не требуется.
- Знание предметной области (технология изготовления батарей) — в объёме своих должностных обязанностей.

## 2.3. Получение учётной записи

Учётную запись (логин и пароль) оператор получает у системного администратора или руководителя лаборатории. Самостоятельная регистрация в системе не предусмотрена.

# 3. Выполнение программы

## 3.1. Вход в систему

### 3.1.1. Запуск программы

Для запуска программы откройте веб-браузер и перейдите по адресу, предоставленному системным администратором:

```
http://<адрес-сервера>:3003
```

Текущая операторская поверхность vanilla v1 обслуживается Express на этом же порту. Адрес `:5173` используется только разработчиками для отдельной Vue parity-поверхности и не является текущим рабочим адресом vanilla v1.

### 3.1.2. Экран входа

После перехода отображается экран входа:

```
┌──────────────────────────────────────────────────────┐
│                                                      │
│                       ЛИМС-ХИТ                        │
│                                                      │
│           ┌────────────────────────────────┐         │
│           │  Логин:      [______________]  │         │
│           │  Пароль:     [______________]  │         │
│           │                                │         │
│           │            [  Войти  ]         │         │
│           └────────────────────────────────┘         │
│                                                      │
└──────────────────────────────────────────────────────┘
```

**Порядок входа:**

1. Введите логин в поле «Логин».
2. Введите пароль в поле «Пароль».
3. Нажмите кнопку «Войти» или клавишу **Enter**.
4. При успешной проверке учётных данных открывается главный экран системы.

### 3.1.3. Неуспешный вход

При неверном логине или пароле отображается сообщение:

> Неверный логин или пароль.

После 10 неудачных попыток входа для данного логина в течение 1 часа доступ блокируется. Для разблокировки обратитесь к системному администратору.

### 3.1.4. Выход из системы

Для выхода:

1. Нажмите на имя пользователя в правом верхнем углу.
2. В выпадающем меню выберите «Выход».

Сессия завершается автоматически через 8 часов бездействия.

## 3.2. Общая навигация

### 3.2.1. Структура главного экрана

```
┌─────────────────────────────────────────────────────────────────┐
│ ЛИМС-ХИТ / BADB                         [Пользователь] [Выход] │
├─────────────────────────────────────────────────────────────────┤
│ Рабочий процесс                                                 │
│ [Ленты] [Электроды] [Батареи] [Модули]                          │
│                                                                 │
│ Справочники                                                     │
│ [Материалы] [Проекты] [Рецептуры] [Пользователи] [Отделы]       │
│ [Сепараторы] [Электролиты]                                      │
└─────────────────────────────────────────────────────────────────┘
```

Элементы:

- **Главная страница `/index.html`:** навигационная витрина vanilla v1 с переходами в рабочие и справочные страницы.
- **Рабочие страницы:** ленты, электроды, батареи; страница модулей открывается как заглушка, сборка модулей не входит в текущий vanilla v1 процесс.
- **Справочные страницы:** материалы, проекты, рецептуры, пользователи, отделы, сепараторы, электролиты.
- **Отчётные страницы:** открываются из карточек сущностей или по прямым URL отчётов.

### 3.2.2. Видимость разделов

Vanilla v1 показывает ссылки на текущие рабочие и справочные страницы. Выполнение операций всё равно проверяется сервером по JWT и роли пользователя:

- обычный сотрудник работает с доступными ему лабораторными данными;
- руководитель и администратор имеют расширенный доступ к справочникам и данным проектов;
- отдельные сценарии вроде управления доступом, аудита и Vue-дэшборда относятся к backend/API или Vue parity-поверхности и не описываются как текущие vanilla-страницы.

### 3.2.3. Индикатор несохранённых изменений

В верхней части формы, рядом с заголовком страницы, может отображаться индикатор состояния:

| Индикатор | Значение |
|---|---|
| *(пусто)* | Изменений нет |
| Охра, «Несохранено» | Есть несохранённые изменения |
| Зелёная галочка | Изменения сохранены (индикатор гаснет через 2 с) |

### 3.2.4. Горячие клавиши

| Клавиша | Действие |
|---|---|
| **Enter** в формах | Сохранить / Войти |
| **Esc** в диалогах | Закрыть диалог |
| **Ctrl+P** | Печать текущего отчёта (для отчётных страниц) |

## 3.3. Профиль пользователя

### 3.3.1. Просмотр и редактирование

Переход: **Имя пользователя → Профиль**, если ссылка профиля отображается в текущей сборке.

Редактируемые поля:

- Отображаемое имя (видимо другим пользователям);
- Отдел (выбор из 4 подразделений: Отдел исследований и разработок ХИТ / Отдел исследований и испытаний / Группа разработки новых материалов / Научно-образовательная группа).

Поля, доступные только для просмотра:

- Логин (неизменяем после создания);
- Роль (назначается администратором);
- Дата создания учётной записи.

### 3.3.2. Смена пароля

1. В разделе «Профиль» нажмите «Сменить пароль».
2. Введите текущий пароль.
3. Введите новый пароль дважды (для подтверждения).
4. Нажмите «Сохранить».

После смены пароля все активные сессии (в том числе на других устройствах) завершаются автоматически; требуется повторный вход.

## 3.4. Работа со справочниками

Справочники открываются с главной страницы vanilla v1 в блоке **Справочники**.

### 3.4.1. Материалы

Центральный справочник системы. Состоит из трёх уровней:

1. **Материал** (абстрактное определение: «Карбонат лития Li₂CO₃», «Поливинилиденфторид PVDF»).
2. **Экземпляр материала** (конкретная партия или приготовленная смесь: «Li₂CO₃ 100% чистый — партия от 2026-03-15», «PVDF раствор 5% в NMP»).
3. **Партия поставки** (информация о закупке: поставщик, лот, даты).

#### 3.4.1.1. Создание нового материала

1. Переход: **Справочники → Материалы**.
2. Нажмите кнопку «**+ Создать материал**».
3. В открывшейся форме заполните:
   - Название (например: «Карбонат лития»);
   - Химическая формула (например: «Li₂CO₃»);
   - Роль: один из значений `активный катодный` / `активный анодный` / `связующее` / `проводящая добавка` / `растворитель` / `другое`;
   - Описание (свободный текст, необязательно).
4. Нажмите «Сохранить».

После создания материала система **автоматически** создаёт:

- один экземпляр с именем «100% чистый» и признаком «пурум»;
- связанную пустую запись «Партия поставки» для данного экземпляра.

#### 3.4.1.2. Создание дополнительных экземпляров

У материала можно создавать дополнительные экземпляры:

- **Чистые закупленные экземпляры** — для каждой новой партии поставки того же материала.
- **Производные экземпляры (смеси, растворы)** — из других экземпляров.

Порядок:

1. На странице материала нажмите «**+ Экземпляр**».
2. Выберите тип:
   - Новая партия того же материала — создаётся пустая партия поставки, её потребуется заполнить.
   - Смесь / раствор — открывается форма ввода компонентов.
3. Заполните:
   - Название экземпляра (свободный текст);
   - Для смеси — добавление компонентов: материал-компонент, массовая доля.
4. Нажмите «Сохранить».

#### 3.4.1.3. Заполнение данных партии поставки

Доступно только для **чистых закупленных экземпляров**. Для производных (смеси, растворы) недоступно.

1. На странице материала напротив чистого экземпляра нажмите «**Источник**».
2. В открывшейся форме заполните:
   - Поставщик;
   - Бренд;
   - Каталожный номер;
   - Номер лота;
   - Дата заказа;
   - Дата получения;
   - Оценка качества: метка (`хорошо` / `нормально` / `плохо` / `не оценено`) и, при желании, числовая оценка (1–5);
   - Примечания оценки.
3. При необходимости приложите документы:
   - Сертификат качества;
   - Паспорт;
   - Фотография упаковки.
   Максимальный размер одного файла — 6 МБ. Поддерживаются форматы: PDF, PNG, JPEG, WEBP.
4. Нажмите «Сохранить».

#### 3.4.1.4. Заполнение свойств материала

Свойства материала (удельная ёмкость, плотность) задаются на уровне **рабочего экземпляра материала** и доступны для редактирования со страницы конкретного экземпляра или связанной записи партии поставки.

1. На странице материала нажмите «**Свойства**».
2. Заполните применимые поля:
   - Удельная ёмкость, мА·ч/г (для активных материалов) — **ключевое значение для расчёта ёмкости батарей**;
   - Плотность, г/мл (для растворителей, растворов) — **ключевое значение для конвертации масса ↔ объём**.
3. Нажмите «Сохранить».

#### 3.4.1.5. Отображение оценки качества в списке

На главной странице «Материалы» у каждого чистого закупленного экземпляра отображается цветной индикатор:

| Цвет | Значение |
|---|---|
| Зелёный | «Хорошо» |
| Серый / синий | «Нормально» |
| Красный | «Плохо» |
| *пусто* | «Не оценено» |

У производных экземпляров и у экземпляров без привязанной партии поставки индикатор не отображается.

### 3.4.2. Рецептуры ленты

Переход: **Справочники → Рецептуры**.

#### 3.4.2.1. Создание рецептуры

1. Нажмите «**+ Создать рецептуру**».
2. Укажите название (например: «Катод NMC 96:2:2»).
3. Добавьте строки рецептуры. Для каждой строки:
   - Выберите материал из справочника;
   - Укажите роль в рецептуре: `катодный активный` / `анодный активный` / `связующее` / `проводящая добавка` / `растворитель` / `другое`;
   - Укажите долю в сухом остатке, % (например: 96.0);
   - Установите флаг «Участвует в процентном расчёте»:
     - Для сухих компонентов (активный, связующее, добавки) — **включено**;
     - Для растворителя — **отключено**.
4. Сумма долей компонентов с включённым флагом должна быть близка к 100 %. Система проверяет это при сохранении.
5. Нажмите «Сохранить».

#### 3.4.2.2. Редактирование рецептуры

Изменения рецептуры не затрагивают уже созданные ленты, использовавшие предыдущую версию. Для создания значительно отличающейся рецептуры рекомендуется создавать новую, а не редактировать существующую.

### 3.4.3. Другие справочники

Справочники **Электролиты**, **Сепараторы**, **Проекты**, **Пользователи** и **Отделы** ведутся по общему принципу:

1. Переход в нужный справочник с главной страницы.
2. Кнопка «**+ Создать**» для добавления записи.
3. Заполнение полей в диалоге или на отдельной странице.
4. Кнопка «**Сохранить**».

Текущие vanilla v1 справочники используют быстрые фильтры над списком. Проекты фильтруются по тексту, статусу, доступу, отделу и руководителю; рецептуры — по тексту и роли; пользователи — по тексту, роли, отделу и активности; отделы — по тексту и руководителю; электролиты — по тексту, статусу и типу; сепараторы — по тексту, статусу и структуре.

Строка списка открывает запись там, где страница поддерживает record-open режим. Открытая запись имеет закреплённую верхнюю панель с названием, краткими метаданными, индикатором несохранённых изменений и кнопками сохранения, выхода, печати или удаления, если они доступны для данной сущности.

Для справочников **Электролиты** и **Сепараторы** файлы сохраняются в БД-связанных секциях «Файлы» и удаляются из открытой записи.

Удаление электролита выполняется из открытой записи. Перед удалением система проверяет связи с батареями; если электролит используется в `battery_electrolyte`, удаление блокируется. Если удаление разрешено, оператор подтверждает действие фразой `DELETE ELECTROLYTE <id>`.

Удаление сепаратора аналогично проверяет связи с батареями и требует фразу `DELETE SEPARATOR <id>`. Рецептуры удаляются после проверки связей и подтверждения `DELETE RECIPE <id>`. Ленты удаляются только пользователем с ролью `admin` или `lead` после проверки связей и подтверждения `DELETE TAPE <id>`. Проекты и пользователи удаляются без typed confirmation, но backend блокирует удаление при зависимостях. Отделы в текущей vanilla v1 странице не имеют удаления.

### 3.4.4. Общие правила работы с таблицами справочников

Общие правила vanilla v1:

- Быстрые фильтры находятся над списком и работают на текущей странице.
- Кнопка «Сбросить» очищает все фильтры, если предусмотрена страницей.
- Строка списка открывает запись или карточку сущности.
- Верхняя панель открытой записи закреплена при прокрутке.
- Печать доступна только на страницах, где реализован специальный отчёт.
- Массового универсального экспорта списков в vanilla v1 нет; экспорт описан отдельно в разделе 3.13.
- Для лент, партий электродов и батарей поле «Дата создания» означает дату создания физического объекта. Оно заполняется сегодняшней датой по умолчанию и может быть перенесено только на сегодня или в прошлое. Системная дата создания записи и дата последнего изменения ведутся автоматически.

## 3.5. Рабочий процесс «Ленты»

Переход: **Процессы → Ленты**.

### 3.5.1. Список лент

На странице «Ленты» отображается таблица всех лент с колонками:

- Идентификатор (ID);
- Название;
- Проект;
- Рецептура;
- Статус (Запланирована / В работе / Завершена);
- Тип нанесения (Одностороннее / Двустороннее);
- Автор;
- Дата создания ленты и дата последнего изменения.

Над списком доступны фильтры по тексту, статусу, проекту, роли рецептуры и типу нанесения. Строка списка открывает конструктор ленты.

### 3.5.2. Создание новой ленты

1. Нажмите «**+ Создать ленту**».
2. В форме создания заполните:
   - Название ленты (свободный текст, обязательно);
   - Проект — выбор из доступных;
   - Рецептура — выбор из созданных;
   - Дата создания — физическая дата создания ленты; по умолчанию сегодня, будущая дата не допускается;
   - Примечания (необязательно).
3. Нажмите «Сохранить».

После создания открывается конструктор ленты с восемью стадиями процесса.

### 3.5.3. Восемь стадий процесса

Конструктор ленты визуально отображает все стадии:

```
┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
│ Матер.   │ Сушка    │ Взвеш.   │ Смеш.    │ Нанес.   │ Сушка    │ Каланд.  │ Фин.     │
│ (0/8)    │ АМ (1/8) │ (2/8)    │ (3/8)    │ (4/8)    │ ленты(5) │ (6/8)    │ сушка(7) │
└──────────┴──────────┴──────────┴──────────┴──────────┴──────────┴──────────┴──────────┘
```

Каждая стадия — отдельная вкладка с полями для ввода параметров. Стадии можно заполнять **в произвольном порядке** (не обязательно последовательно).

#### 3.5.3.1. Стадия 1. Подготовка материалов

Отображает строки рецептуры, выбранные экземпляры материалов, плановые
количества для взвешивания и поля для заполнения **фактических значений**:

| Материал | Роль | Теор. доля, % | План, г | Режим | Факт. значение | Пересчёт |
|---|---|---|---|---|---|---|
| Li₂CO₃ | актив. кат. | 96.0 | рассчитано | масса / объём | [ ____ ] г | ≈ __ мл |
| PVDF | связ. | 2.0 | рассчитано | масса / объём | [ ____ ] г | |
| Super P | доб. | 2.0 | рассчитано | масса / объём | [ ____ ] г | |
| NMP | раств. | — | — | объём | [ ____ ] мл | ≈ __ г |

**Правила:**

- Сначала выберите рецепт, режим расчёта и целевую массу в верхней части
  карточки ленты.
- Выберите конкретный экземпляр материала для каждой строки рецепта. После
  выбора экземпляров система рассчитывает плановые массы для взвешивания.
- Для режима «по массе активного материала» целевая масса трактуется как
  требуемая масса активного материала; остальные сухие компоненты рассчитываются
  по процентам рецепта.
- Для режима «по общей массе суспензии» расчёт выполняется по включённым
  процентным строкам рецепта; строки, исключённые из процентного расчёта
  (например растворитель), заполняются как фактические значения.
- Если выбранный экземпляр сам является смесью, система учитывает его состав и
  показывает массу этого экземпляра, которую нужно взвесить.
- Выберите режим ввода: по **массе** (если материал взвешен) или по **объёму** (если измерен пипеткой/дозатором).
- Укажите значение.
- Для материалов с заполненной плотностью в свойствах система автоматически отобразит эквивалентное значение в другом режиме. Автоматически рассчитанное значение показывается меньшим шрифтом под введённым.
- Если материал — растворитель, а плотность не указана — будет показано предупреждение: «Плотность не указана: масса не может быть рассчитана автоматически». Это не мешает сохранению, но делает расчёт фактической ёмкости невозможным.

#### 3.5.3.2. Стадия 2. Сушка активного материала

Поля:

- Температура, °C;
- Длительность, мин;
- Атмосфера (выбор из справочника: воздух / аргон / вакуум / ...);
- Время начала (автоматически при старте стадии или вручную);
- Время окончания.

Кнопка «**Начать стадию**» автоматически записывает текущее время. Кнопка «**Завершить стадию**» — аналогично.

#### 3.5.3.3. Стадия 3. Взвешивание

Стадия моделируется через фактические значения, введённые на стадии 1. Отдельных полей не имеет (@уточнить — если это изменится, обновить документ).

#### 3.5.3.4. Стадия 4. Смешивание

Поля:

- Метод смешивания (выбор из справочника: планетарный миксер / магнитная мешалка / ...);
- Скорость, об/мин;
- Длительность, мин;
- Объём суспензии;
- Вязкость, мПа·с;
- Условия измерения вязкости, например шпиндель и скорость (`#3, 6 об/мин`);
- Время начала / окончания.

#### 3.5.3.5. Стадия 5. Нанесение покрытия

**Ключевая стадия.** Поля:

- **Тип нанесения:** `Одностороннее` / `Двустороннее` — **обязательный параметр**. Выбранное значение наследуется всеми электродами, нарезанными из этой ленты.
- Метод нанесения (выбор из справочника);
- Зазор, мкм;
- Скорость, м/мин;
- Дополнительные параметры оборудования.

> **Важно:** после того как из ленты нарезаны электроды и они использованы в сборке батареи, изменение типа нанесения не допускается.

#### 3.5.3.6. Стадия 6. Сушка ленты

Аналогично стадии 2.

#### 3.5.3.7. Стадия 7. Каландрирование

Поля:

- Давление, МПа;
- Толщина до, мкм;
- Толщина после, мкм;
- Температура валков, °C;
- Время начала / окончания.

#### 3.5.3.8. Стадия 8. Финальная сушка

Аналогично стадии 2 (сушка каландрированной ленты).

### 3.5.4. Сохранение и завершение

Сохранение выполняется кнопками страницы и стадий; индикатор в верхней части страницы показывает наличие несохранённых изменений и успешное сохранение.

Статус ленты рассчитывается по заполненности обязательных данных workflow. После завершения восьми стадий лента используется как источник для партий электродов.

### 3.5.5. Печать отчёта по ленте

На странице конструктора нажмите «**Печать**» (или **Ctrl+P**). Откроется окно предварительного просмотра печати со сформированным отчётом.

Отчёт содержит:

- Общую информацию о ленте;
- Рецептуру и фактические значения;
- Параметры всех восьми стадий;
- Автора и даты.

## 3.6. Рабочий процесс «Электроды»

Переход: **Процессы → Электроды**.

### 3.6.1. Список партий электродов

Отображается таблица партий нарезки с колонками:

- ID партии;
- Лента-источник;
- Тип нанесения ленты (одностороннее / двустороннее);
- Форма (круг / прямоугольник / pouch);
- Размеры;
- Количество электродов;
- Средняя ёмкость (теор.), мА·ч;
- Дата создания партии;
- Статус.

Над списком доступны фильтры по тексту, статусу, проекту, роли рецептуры, форме, типу нанесения и sidedness. При выборе ленты-источника в форме создания отображаются связанные партии и параметры выбранной ленты.

### 3.6.2. Создание партии нарезки

1. Нажмите «**+ Создать партию**».
2. Выберите ленту-источник из выпадающего списка. В списке отображается тип нанесения: `Лента «XYZ» (двустороннее)`.
3. Выберите форму электрода:
   - Круг — введите диаметр, мм;
   - Прямоугольник — введите ширину × высоту, мм;
   - Pouch — введите размер корпуса.
4. Укажите целевой форм-фактор батареи (`coin` / `pouch` / `prism` / `cylindrical`) и код конфигурации (например, `2032` для монеты диаметром 20 мм толщиной 3.2 мм), если применимо. `prism` отображается как «Призматическая» и в v1.1 использует прямоугольную геометрию как pouch.
5. При необходимости скорректируйте дату создания партии. По умолчанию используется сегодняшняя дата; будущая дата не допускается.
6. Нажмите «Создать».

### 3.6.3. Ввод измерений массы фольги

Для расчёта массы покрытия требуется знать массу фольги-токосъёмника. Выполните:

1. На странице партии в разделе «Измерения массы фольги» нажмите «**+ Добавить измерение**».
2. Введите массу, г.
3. Повторите для нескольких образцов фольги той же партии (обычно 3–5 измерений).
4. Система автоматически рассчитает среднее.

### 3.6.4. Регистрация индивидуальных электродов

1. В разделе «Электроды» нажмите «**+ Добавить электрод**» *или* «**Добавить N электродов**» для пакетного ввода.
2. Для каждого электрода введите массу, г.
3. В колонке «В расчёт» оставьте галочку для электродов, которые должны участвовать в средних значениях ёмкости партии. Снятие или установка галочки сохраняется сразу для конкретного электрода.
4. При необходимости спишите электрод через кнопку действия и укажите причину. Списание — это статус жизненного цикла; оно не меняет галочку «В расчёт» автоматически.

### 3.6.5. Расчёт ёмкости

Сводка расчёта отображается в верхней части страницы партии. Показатели:

| Показатель | Единица | Описание |
|---|---|---|
| Средняя масса фольги | г | Среднее по введённым измерениям |
| Активная материал | — | Название |
| Удельная ёмкость | мА·ч/г | Из свойств материала |
| Доля активного (теор.) | % | Из рецептуры |
| Доля активного (по факт. массе) | % | Из фактических значений ленты |
| Средняя масса покрытия | г | По электродам с отметкой «В расчёт» |
| Средняя масса активного (теор.) | г | |
| Средняя масса активного (по факт. массе) | г | |
| Средняя ёмкость электрода (теор.) | мА·ч | |
| Средняя расчётная ёмкость электрода (по факт. массе) | мА·ч | |
| Поверхностная ёмкость (теор.) | мА·ч/см² | |
| Ёмкость на сторону (теор.) | мА·ч/см² | С учётом типа нанесения |
| Количество в среднем | — | Электроды с отметкой «В расчёт» |

В таблице электродов каждая строка содержит индивидуально рассчитанную ёмкость
и флаг «В расчёт». Статус электрода (`доступен`, `использован`, `списан`) и
участие в среднем расчёте независимы: списанный электрод можно включить в
среднее вручную, а тонкий или нерепрезентативный электрод можно исключить без
списания. При миграции старых данных списанные электроды начинают как
исключённые, остальные — как включённые.

Кнопка «**Видимость столбцов**» (над таблицей) позволяет скрыть или показать вычисляемые столбцы (масса покрытия, массы активного, ёмкости).

### 3.6.6. Печать отчёта по партии

Аналогично ленте — кнопка «Печать» или Ctrl+P. Отчёт включает полную сводку
расчёта и показывает по каждому электроду, участвовал ли он в средних значениях
ёмкости.

## 3.7. Рабочий процесс «Батареи»

Переход: **Процессы → Сборка**.

Над списком аккумуляторов доступны быстрые фильтры: поиск по идентификатору,
видимой строке списка, заметкам, проекту и размеру/конфигурации; фильтр по
статусу; фильтр по форм-фактору. В фильтре статусов служебные пустые значения и
старые `disassembled` отображаются как «Открыт». Кнопка «Сбросить» очищает все
фильтры.

### 3.7.1. Создание новой батареи

1. Нажмите «**+ Создать батарею**».
2. Заполните:
   - Форм-фактор: `Монета` / `Pouch` / `Призматическая` / `Цилиндрическая`.
   - Дата создания — физическая дата создания батареи; по умолчанию сегодня, будущая дата не допускается.

> **Примечание.** У батарей нет отдельного поля «Название» — идентификация производится по системному идентификатору `battery_id` (числовой). Произвольное описание можно ввести в поле «Примечания к батарее» (`battery_notes`).
3. Для форм-фактора **«Монета»** дополнительно укажите:
   - Режим ячейки: `Полуячейка` (код БД: `coin_cell_mode='half_cell'`) или `Полная монета` (`coin_cell_mode='full_cell'`);
   - Типоразмер корпуса (`coin_size_code`): 2016 / 2025 / 2032;
   - Раскладку стека (`coin_layout`): `SE` / `ES` / `ESE` — порядок слоёв;
   - Параметры проставок (толщина, количество).
4. Для форм-фактора **Pouch** или **Призматическая** дополнительно укажите размер корпуса (`pouch_case_size`). В v1.1 призматический элемент использует тот же config path, пока отдельные prism-поля не определены лабораторией.
5. Для **цилиндрической** — диаметр и высоту.
6. Нажмите «Создать».

Проектная принадлежность батареи задаётся через выбранные источники электродов и связи с проектами. Vanilla v1 ограничивает доступные project links проектами исходных партий электродов.

### 3.7.2. Выбор источников электродов

В разделе «Источники электродов»:

1. Нажмите «**+ Добавить источник**».
2. Выберите ленту и партию нарезки.
3. Укажите роль: `Катод` / `Анод`.

**Ограничения по форм-фактору и режиму:**

| Конфигурация | Правило |
|---|---|
| Монета + полуячейка (`half_cell`) | Ровно один источник (либо катод, либо анод) |
| Монета + полная (`full_cell`) | Ровно один катод и ровно один анод |
| Pouch | Ровно один катод и ровно один анод |
| Призматическая | Ровно один катод и ровно один анод |
| Цилиндрическая | Ровно один катод и ровно один анод |

При попытке нарушения ограничения система отображает сообщение: «Для выбранного форм-фактора этот набор источников недопустим».

### 3.7.3. Выбор электродов в стек

1. В разделе «Электроды в стеке» нажмите «**+ Добавить электрод**».
2. Выберите электрод из выбранной партии.
3. Укажите позицию в стеке.

**Правила:**

- Нельзя смешивать электроды с разным типом нанесения ленты-источника. При попытке — сообщение: «Нельзя смешивать 1- и 2-сторонние электроды в одной ячейке».
- Нельзя использовать электроды со статусом «Брак».
- Для монетной полуячейки (`coin` + `half_cell`): один электрод.
- Для монетной полной (`coin` + `full_cell`): один катод + один анод.
- Для Pouch / призматической / цилиндрической: анодов должно быть столько же, сколько катодов, или на один больше; лишний катод запрещён.
- При сохранении Pouch / призматического / цилиндрического стека система сама передаёт строки в БД в безопасном порядке `A1, C1, A2, C2`, сохраняя заданные пользователем позиции. На экране стек читается по `position_index`, а не по техническому порядку INSERT.

### 3.7.4. Выбор электролита и сепаратора

В разделах «Электролит» и «Сепаратор» выберите значения из справочников. При необходимости укажите объём электролита, мл.

### 3.7.5. Параметры сборки

В разделе «Сборка» заполните:

- Дата сборки;
- Оператор;
- Давление (для монетных) / метод герметизации (для pouch);
- Состояние dry-box-а (тип газа, влажность);
- Примечания.

### 3.7.6. Статус аккумулятора

Поле «Статус аккумулятора» показывает текущее состояние записи:

- до заполнения обязательных записей сборки поле заблокировано и показывает
  «Открыт»;
- после заполнения обязательных записей сборки система устанавливает «Собран»;
- после сборки оператор может выбрать только «Собран», «На тестировании»,
  «Завершён» или «Брак».

Статус «Открыт» не выбирается вручную. Старые записи со служебным значением
`disassembled` отображаются как «Открыт» и могут быть собраны повторно в той же
карточке при сохранении новых данных сборки.

### 3.7.7. Контроль качества (QC)

После сборки заполните раздел «QC»:

- Масса собранной батареи, г;
- Толщина, мм;
- Результаты визуального осмотра;
- Дата выполнения;
- Оператор.

### 3.7.8. Загрузка файлов электрохимических испытаний

В разделе «Электрохимические испытания» можно загружать файлы первичных испытаний и сохранять текстовые заметки без файла.

1. Нажмите «**+ Загрузить файл**» или перетащите файлы в область загрузки.
2. Несколько файлов загружаются последовательно; заметку можно сохранить отдельной строкой без файла.
3. После загрузки файлы/заметки отображаются в списке; файл можно открыть по ссылке, каждую строку можно удалить.

### 3.7.9. Удаление ошибочной записи аккумулятора

Удаление аккумулятора используется только для ошибочно созданных записей, а не
для фиксации реального лабораторного исхода.

1. Откройте аккумулятор и нажмите «Удалить запись».
   После нажатия страница прокручивается к верхней части карточки, где
   отображается направляемый блок удаления.
2. Система выполнит preflight-проверку. Циклирование и принадлежность к модулю
   являются hard blockers.
3. Если есть связанные электроды, выберите, вернуть их как доступные или как
   списанные.
4. На финальном шаге проверьте список battery-owned данных, которые будут
   удалены.
5. Введите `DELETE BATTERY <id>` и подтвердите удаление.

Успешное удаление пишет событие `activity_log`. Доступ к guided delete открыт
любому аутентифицированному пользователю по утверждённой архитектуре.

### 3.7.10. Сводка электрохимических показателей

Автоматически отображается в верхней части страницы:

| Показатель | Единица |
|---|---|
| Σ катодов (теор.) | мА·ч |
| Σ катодов (по факту) | мА·ч |
| Σ анодов (теор.) | мА·ч |
| Σ анодов (по факту) | мА·ч |
| Лимитирующая ёмкость (теор.) | мА·ч |

Для полуячеек (монета с режимом `half_cell`) отображается только ёмкость рабочего электрода.

### 3.7.11. Печать отчёта по батарее

Кнопка «Печать» или Ctrl+P. Отчёт содержит полную информацию о батарее: состав, QC, электрохимические показатели, приложенные файлы *(список, без содержимого)*.

## 3.8. Электрохимические испытания (циклирование)

В текущей vanilla v1 поверхности отдельной страницы циклирования нет. Данные электрохимических испытаний, относящиеся к батарее, загружаются и просматриваются в карточке батареи в разделе «Электрохимические испытания» (см. 3.7.8).

Backend API циклирования поддерживает загрузку протоколов, парсинг через `scripts/parse_cycling.py`, таблицы `cycling_sessions`, `cycling_datapoints`, `cycling_cycle_summary` и экспорт CSV/XLSX. Графики и стилевые пресеты относятся к отдельной Vue frontend synchronization/handoff поверхности и не описываются как текущее vanilla v1 поведение.

## 3.9. Аналитика и дашборды

### 3.9.1. Главная страница

Переход: главная страница `/index.html`.

В vanilla v1 главная страница выполняет навигационную роль: содержит ссылки на рабочие страницы, справочники и текущие отчётные сценарии. Аналитические KPI, графы, воронки и Gantt-представления реализуются backend API `/api/dashboard` и Vue parity-поверхностью; они не являются текущей vanilla v1 страницей.

### 3.9.2. Взаимодействие

Клик по ссылке на главной странице открывает соответствующую vanilla v1 страницу.

## 3.10. Аудит изменений

### 3.10.1. Просмотр истории изменений объекта

Append-only журналы `auth_log`, `activity_log` и `field_changelog` ведутся backend-ом. Текущие vanilla v1 страницы не имеют универсальной вкладки истории на каждой карточке; если конкретная страница показывает историю, она должна использовать эти журналы как источник данных.

### 3.10.2. Общий журнал активности

Для ролей `Руководитель` и `Администратор`:

Отдельная лента активности относится к backend API `/api/dashboard/activity` и Vue parity-поверхности. В vanilla v1 operator surface она не является отдельной текущей страницей.

### 3.10.3. Журнал аутентификации

Для ролей `Руководитель` и `Администратор`:

Журнал входов и выходов хранится в `auth_log`. Просмотр через отдельную административную Vue-страницу рассматривается как frontend synchronization/handoff concern.

## 3.11. Обратная связь

Таблица `feedback` и API обратной связи присутствуют как поддерживающая подсистема. В текущем vanilla v1 наборе рабочих и справочных страниц отдельная форма обратной связи не является операторской страницей.

1. Нажмите «**+ Новое сообщение**».
2. Выберите категорию: `Баг` / `Предложение` / `Вопрос` / `Другое`.
3. Опишите суть.
4. При необходимости прикрепите файлы (скриншоты, образцы).
5. Нажмите «Отправить».

Просмотр и обработка обратной связи относятся к backend/API или Vue parity-поверхности.

## 3.12. Печатные отчёты

Для лент, партий электродов, батарей, проектов, рецептур, электролитов и сепараторов предусмотрены печатные формы. Запуск:

- Кнопка «**Печать**» на странице сущности;
- Сочетание **Ctrl+P** на странице сущности.

Отчёт открывается во всплывающем окне предварительного просмотра. Можно:

- Напечатать на принтере;
- Сохранить в PDF через функцию браузера «Сохранить как PDF».

## 3.13. Экспорт данных

### 3.13.1. Экспорт списков

Универсального экспорта всех vanilla v1 списков в CSV/XLSX/JSON нет. Если конкретная страница содержит кнопку экспорта, следует пользоваться подсказками этой страницы.

### 3.13.2. Экспорт циклирования и отчётов

Текущий backend поддерживает экспорт данных циклирования через API (`GET /api/cycling/sessions/:id/export`, `GET /api/cycling/export/xlsx`). Печатные vanilla-отчёты сохраняются в PDF штатной функцией браузера «Печать → Сохранить как PDF».

## 3.14. Управление доступом (для руководителей)

Доступно только ролям `Руководитель` и `Администратор` через API управления доступом и отдельную Vue parity-поверхность. В текущем vanilla v1 наборе страниц управление доступом не является отдельной рабочей страницей.

### 3.14.1. Матрица доступа

Основной экран — матрица «Пользователи × Проекты». Клетки показывают текущий уровень доступа пользователя к проекту:

- Пусто — доступа нет;
- Значок роли (исполнитель / руководитель проекта) + срок действия.

### 3.14.2. Предоставление доступа

1. На пересечении пользователя и проекта нажмите на клетку.
2. В открывшемся диалоге:
   - Выберите роль;
   - Укажите срок действия (бессрочно или до конкретной даты).
3. Нажмите «Сохранить».

### 3.14.3. Отзыв доступа

1. Нажмите на клетку с существующим доступом.
2. В диалоге нажмите «Отозвать».

### 3.14.4. Хронология изменений доступа

Вкладка «Хронология» показывает все операции предоставления и отзыва доступа с указанием исполнителя и даты.

| Сообщение | Причина | Действие оператора |
|---|---|---|
| «Неверный логин или пароль» | Введены неверные учётные данные | Проверить и ввести заново |
| «Учётная запись временно заблокирована. Обратитесь к администратору.» | 10 неудачных попыток входа в течение часа | Обратиться к администратору |
| «Сервер недоступен. Попробуйте позже.» | Нет связи с сервером | Проверить сеть; обратиться к администратору |
| «Сессия истекла. Требуется повторный вход.» | Токен просрочен (8 часов) или принудительно инвалидирован | Повторно войти в систему |
| «Недостаточно прав для выполнения действия.» | У роли нет разрешения | Обратиться к руководителю |
| «Форма содержит ошибки. Проверьте поля, помеченные красным.» | Некорректные данные в форме | Исправить ошибки по подсказкам |
| «Запись была изменена другим пользователем. Обновите страницу и повторите.» | Конфликт оптимистичной блокировки | Обновить страницу; внести изменения заново |
| «Превышен размер файла. Максимум — 6 МБ.» | Файл превышает лимит | Сжать или разделить файл |
| «Файл не поддерживается.» | Неправильный формат | Конвертировать в допустимый формат |
| «Для выбранного форм-фактора этот набор источников недопустим.» | Нарушено правило форм-фактора | Пересмотреть набор электродов |
| «Нельзя смешивать 1- и 2-сторонние электроды в одной ячейке.» | Выбран электрод с другим типом нанесения | Выбрать электроды с согласованным типом нанесения |
| «Плотность не указана: масса не может быть рассчитана автоматически.» | У материала не заполнена плотность | При необходимости — заполнить плотность в справочнике материалов |
| «Сумма долей компонентов не равна 100%.» | Рецептура содержит ошибку в долях | Пересмотреть доли компонентов |

## 4.3. Действия при критических ошибках

Если страница не открывается, интерфейс не отвечает или появляются повторяющиеся ошибки, выполните по очереди:

1. Обновите страницу браузера (**F5** или **Ctrl+R**).
2. Выйдите из системы и войдите снова.
3. Очистите кэш браузера и попробуйте ещё раз.
4. Проверьте сетевое соединение.
5. Обратитесь к системному администратору, указав:
   - Время возникновения проблемы;
   - Действия, которые выполнялись;
   - Точный текст сообщения об ошибке;
   - Скриншот, если возможен.
