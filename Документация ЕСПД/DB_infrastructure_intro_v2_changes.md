# Ревью DB_infrastructure_intro_v2

Файл `DB_infrastructure_intro_v2.md` рассматривается как рабочее предложение к
инфраструктурной вводной, а не как авторитетная замена версии Мараулайте Д.К.
Итоговый документ должен сохранять текущую структуру ответственности и
терминологию проекта.

## Принятая терминология

По назначению система относится к классу лабораторных информационных систем
(ЛИС/ЛИУС; англ. LIMS), но рабочее наименование разрабатываемого решения:
**«Протоколы сборки лаборатории ХИТ»**. Техническое обозначение в коде и БД:
**BADB** (*Battery Assembly Database*).

Не использовать **«ЛИМС-ХИТ»** как рабочее название продукта. Термины
**ЛИС/ЛИУС/LIMS** допустимы только как классификация.

## Принятая структура ответственности

- **Ответственный исполнитель / функциональный владелец / руководитель разработки:**
  Мараулайте Д.К.
- **Соразработчик / технический исполнитель по отдельным модулям, Vue/V2,
  инфраструктуре:** Меняйлов Д.С.
- **Электрохимическая экспертиза:** Баталов Р.С. факультативно.

Для frontmatter ЕСПД использовать:

```yaml
author: Мараулайте Д.К.
contributors: Меняйлов Д.С.
reviewer: @уточнить
```

## Что из v2 стоит учесть

- Более сильное описание требований к инфраструктуре: RAM, SSD/NVMe, Node.js
  22 LTS, PostgreSQL 16.x.
- Явное разделение PostgreSQL как источника структурированных данных и
  `uploads/` как файлового хранилища, которое тоже нужно резервировать.
- Более подробное описание backup-инструментария и необходимости регламента
  хранения/проверки восстановления.
- Явный пункт о том, что решение не обращается к внешним API/облачным сервисам.
- Честное описание открытых вопросов безопасности: HTTPS, MFA, шифрование
  бэкапов, приватность `/uploads`.
- Уточнение роли Vue/V2: V2 содержит часть будущей/расширенной функциональности,
  но текущая рабочая vanilla v1 остаётся операторской baseline-поверхностью.

## Что не принимать без правки

- Формулировки, где `DB_infrastructure_intro_v2.md` выглядит как
  авторитетная замена версии Мараулайте Д.К.
- Любые места, где Меняйлов Д.С. указан единственным автором/ответственным за
  ЕСПД или за продукт в целом.
- Любые места, где **«ЛИМС-ХИТ»** подаётся как название продукта.

Итоговая вводная для IT/Гринатома должна быть краткой, технической и
согласованной с ЕСПД, но без политически неверной подмены названия продукта или
структуры ответственности.
