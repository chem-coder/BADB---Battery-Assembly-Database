# HOW_TO Systematize Documents

Created: 2026-05-06
Edited: 2026-05-06
Status: instruction

Use this process to turn scattered notes, markdown files, text files, and converted Word documents into a small, useful documentation system.

## Where Dalia Should Put Documents For Review

Put files here:

```text
/Users/Dalia/Developer/RENERA/BADB_main/docs/archive/inbox/
```

This is the only raw drop zone. It can temporarily contain `.md`, `.txt`,
`.docx`, PDFs, screenshots, and messy notes. Raw inbox files are not source of
truth.

First normalization step: convert every document-like file to `.md` and remove
the original non-md file. The docs system is markdown-only after normalization.
Ignore gitignored operating-system metadata such as `.DS_Store`; it is not a
documentation source and may reappear on Macs.

Recommended optional naming:

```text
YYYY-MM-DD_topic_short-description.ext
```

Examples:

```text
2026-05-06_batteries_old-delete-notes.md
2026-05-06_materials_dima-generated-spec.docx
2026-05-06_future-dashboard-ideas.txt
```

## Triage Categories

Assign each file or section to one of four useful buckets:

| Bucket | Meaning | Destination |
|---|---|---|
| Existing feature description | What the system does now. Must be checked against code. | `docs/current/` |
| Rule | Constraint that agents/colleagues must follow. | `docs/rules/` |
| Instruction | How to perform a recurring task. | `docs/instructions/` |
| Future idea | Useful idea, not implemented or not promised. | `docs/future/` |

If a file is wrong but historically useful, move it to `docs/archive/superseded/` and record the reason.

If a file is generated by a colleague/AI and not trusted, move it to `docs/archive/external_generated/` and record the reason.

## Approval Model

Dalia does not need to approve every triage move. Agents should reduce the
review burden by staging work clearly.

Allowed without asking first:

- inventorying inbox files;
- classifying documents;
- moving raw/untrusted/stale documents inside `docs/archive/`;
- extracting verified facts into draft canonical docs;
- updating `docs/INDEX.md` and folder READMEs;
- marking a document as `future idea`, `raw inbox`, `superseded`, or `external generated`.

Ask before:

- permanently deleting anything;
- changing a `Status: rule` document in a way that changes behavior;
- declaring an existing-feature doc fully current without code/migration/test
  verification;
- changing source-of-truth order, migration policy, auth policy, or release
  gates;
- moving documents outside the docs system.

Good final report format:

```text
Reviewed:
- file A -> extracted into docs/current/batteries.md
- file B -> staged as docs/archive/superseded/file B because ...
- file C -> kept in inbox because ...

Needs Dalia decision:
- only the 1-3 items that genuinely need judgment
```

## Triage Workflow For Agents

1. Inventory the inbox files.
2. Convert non-markdown document files to `.md`, verify the converted files are
   nonempty, and remove the original non-md files. Ignore gitignored
   operating-system metadata such as `.DS_Store`.
3. For each markdown file, identify topic, status, likely owning domain, and risk.
4. Extract only still-useful information.
5. Verify existing-behavior claims against code, migrations, and tests.
6. Merge verified content into the smallest possible canonical document.
7. Mark future ideas clearly as future ideas.
8. Archive stale/untrusted originals inside `docs/archive/`; ask only before permanent deletion or policy changes.
9. Update `docs/INDEX.md`.
10. Update `Документация ЕСПД/` only after the working docs are coherent.

## Compression Rule

Do not preserve every sentence. Preserve:

- current facts;
- hard rules;
- decisions and reasons;
- tests/checks that prove behavior;
- future ideas worth considering.

Delete or archive:

- duplicated prose;
- stale implementation claims;
- old plans already implemented;
- generated filler;
- instructions that no longer match the repo.

## ЕСПД Mirror Rule

`Документация ЕСПД/` is a formal mirror. It should be updated from:

- `docs/current/`;
- `docs/rules/`;
- `docs/instructions/`;
- current code and migrations.

Do not use `Документация ЕСПД/` as the place where raw notes or future ideas start.
